# module_macros — сценарии на реальном Lua + встроенный cron

> **Опциональный модуль.** Подключается через `src_filter` + `build_flags`.
> **Работоспособен только в составе сборки, содержащей ядро** (см. `../../TRS.md` §2.1).

Модуль `module_macros` превращает прошивку AVR-FOTA (ESP32) в устройство с **пользовательскими
сценариями**: файлы-сценарии — это **настоящий Lua 5.4**, тело которого исполняется раз в секунду.
Сценарий читает/пишет ресурсы прошивки через namespace-таблицы (`time.hour`, `e7.brightness`,
`wifi.connected`), вызывает функции (`e7.speed(50)`), планирует себя (`every`, `after`, `once`,
`tick`) и реагирует на события (`on`, `term`, `button`).

- **Репозиторий:** https://github.com/Arcanum753/module_macros
- **Папка:** `src/module_macros/`
- **Флаг активации:** `-D MODULE_MACROS=1`
- **Registry:** `object=module_macros`, `define=MODULE_MACROS`, `namespace=macros`, `web=1`, `loop=0`, `res=1`, `prio=60`, `priv=1`
- **Только для платформы:** ESP32
- **Зависит от модулей:** —
- **Зависит от ядра:** `core_web`, `core_sys`, `core_json`, `core_state` (ресурсная шина), `core_ntp` (cron требует синхронизации времени), `core_terminal`

Содержимое:
- веб-страница-менеджер файлов сценариев (`/macros.html`);
- веб-страница управления модулями (`/state.html`): список namespace и переключение режимов
  `off/auto/macro` (перенесена из `core_state`; данные — через `core_state.modulesInfo()`,
  смена — через `core_state.moduleMode()`);
- набор Lua-сценариев в папке файловой системы `/macros/*.lua`;
- интерпретатор **Lua 5.4.7** (движок **EspLuaEngine**, вендорен в `EspLuaEngine/`);
- планировщик cron на базе **ccronexpr** (supertinycron) + time-мост на `common/TimeLib`;
- метафайл `/config_macros.json` (список, приоритеты, состояния, даты создания);
- отладка и управление через терминал (команды `macro ...`).

Модуль предназначен **только для ESP32** (поддержка ESP8266 удалена).

---

## 1. Что это и зачем

Прошивка получает гибкую «логику пользователя», которую не нужно перекомпилировать. Сценарий —
обычный Lua-чанк, у которого **нет обязательного формата**:

```lua
-- Ночью при слабом свете — приглушить яркость.
if time.hour >= 22 and veml7700.available and veml7700.lux < 20 then
    e7.brightness = 5
end
```

Тело файла исполняется на каждом тике (раз в секунду) в главном цикле. Модуль держит **один**
Lua-интерпретатор на всё устройство; чанк компилируется один раз при запуске и вызывается
на каждом тике. Всё — реальные операторы Lua (`if`/`for`/функции/замыкания), без DSL-ключевых
слов вроде `when`/`rules`/`cond`/`meta_cron`.

## 2. Как подключить и собрать

Окружение-прототип описано в `src/module_macros/module_macros.ini`.

Сборка (файл `src/modules_registry.cpp` автогенерируется под выбранный env):

```bash
python python/module_registry_gen.py --env esp32_electronica7_rgb_macros
pio run -e esp32_electronica7_rgb_macros
```

Флаги макрос-окружения:
- `DEBUG_MACROS` — журнал модуля (не гейтится `RELEASE`);
- `RELEASE` — гасит общие логи (`DEBUGLOG` core_web/json);
- `DEBUGLOG_WIFI` — логи Wi-Fi.

**Важно:** все ESP32 env используют единую таблицу `partitions_esp32.csv`
(лежит в корне ядра): app0/app1 по 1472 КБ, spiffs 1080 КБ. Путь форсируется
pre-script `python/0_esp32_common.py`.

После прошивки:
1. Модуль создаёт каталог `/macros/` (если его нет). Файлы-примеры приходят с файловой
   системой (см. `src/module_macros/web/macros/*.lua`), `4_fs_builder.py` раскладывает их
   в образ FS с сохранением подкаталога.
2. При первом проходе список файлов синхронизируется с метафайлом `/config_macros.json`
   (новые `.lua` добавляются с приоритетом 7 и в состоянии «стоп», записи об отсутствующих
   файлах удаляются).
3. Откройте `/macros.html` или воспользуйтесь терминалом.

## 3. Веб-страница `/macros.html`

Страница-менеджер файлов сценариев.

### Таблица-список
Колонки (порядок можно менять, перетаскивая заголовки; порядок сохраняется в
`localStorage` браузера):
- чекбокс выбора;
- **приоритет** (0 — высший, 7 — низший);
- имя файла;
- число обработчиков;
- состояние: «запущен» / «стоп» / «ошибка» (текст ошибки — в всплывающей подсказке);
- дата создания.

Клик по строке выделяет её и открывает файл во **встроенном** редакторе страницы.
При сборке с `module_editor` рядом с `Validate`/`Save` появляется кнопка
**Open in editor**, ведущая на `edit.html?file=/macros/<name>` (новая вкладка).

### Кнопки панели (сверху)
- **Обновить список**, **Создать**, **Запустить**/**Остановить**, **Перечитать**,
  **Редактировать**, **Переименовать**, **Приоритет − / +**, **Удалить**,
  **Валидация макросов** (показывает `/macros/heap`).
- Правила активности и «запущенный сценарий — только просмотр» — как раньше.

### Веб-API (все — GET, состояние в query)
| URL | Назначение |
|-----|-----------|
| `/macros/list` | JSON-список файлов (`name`, `prio`, `run`, `size`, `created`, `active`, `handlers`, `desc`, `err`) |
| `/macros/create?name=` | создать файл сценария |
| `/macros/delete?name=` | удалить (имена через запятую) |
| `/macros/rename?old=&new=` | переименовать |
| `/macros/state?name=&on=1|0` | запустить/остановить |
| `/macros/prio?name=&dir=+1|-1` | изменить приоритет |
| `/macros/reload?name=` | перечитать (без name — все) |
| `/macros/fire?type=&token=` | внешнее событие (`term`/`button`) |
| `/macros/validate?cron=&body=` | проверка cron и сценария: компиляция + пробный прогон тела (без побочных действий) |
| `/macros/get?name=` / `/macros/save?name=&body=` | чтение/запись сценария |
| `/macros/ver` | версия модуля (также используется страницей `state.html`) |
| `/state/modules` | JSON-список модулей (namespace) и их режимов |
| `/state/module_mode?ns=&mode=` | смена режима модуля `off/auto/macro` |

Файлы `.lua` открываются в `module_editor` (`edit.html`) как текстовые.

### Каталог ресурсов (дерево Resources)

Список ресурсов страница берёт из `/macros/resources.json` — статического файла в образе ФС.
Он собирается **автоматически при сборке ФС** (`python/gen_resources_catalog.py`, шаг 7b в
`python/4_fs_builder.py`) из вызовов `regState`/`regStateAs`/`regEnum`/`regFunc`/`regEvent`
компонентов, включённых в `src_filter` (+ все `core_*`); namespace — из `[registry]`
их `.ini` (или имени каталога) с переопределением через `setNamespace(...)` в `.cpp`.
Рантайм-эндпоинта `/macros/resources` больше нет.

- Файл в репозитории не хранится и вручную не правится — при следующей прошивке ФС он
  перезаписывается.
- Чтобы ресурс появился в дереве, он должен быть зарегистрирован в коде **литеральной строкой**.
- Имена, собранные динамически (конкатенация/переменная), в каталог не попадают.
- `regFuncAsync` генератор не парсит: асинхронные функции в каталог не попадают, флаг `a`
  в файле всегда `false`.
- Формат записи: `ns`, `name`, `full`, `kind`, `desc`, `rw`, `e` (есть событие), `f` (есть
  функция), `a` (async), `enum` (значения ENUM). Корень:
  `{"features":{"editor":0|1},"resources":[…]}`; `editor=1` при сборке с `module_editor`.

Ответственность за актуальность списка — на регистрациях в коде компонентов, а не на файле.

## 4. Терминал

Команды регистрируются модулем лениво при первом вызове `TerminalLoop()`:

```
macro list                         — список сценариев и число обработчиков
macro run <file.lua>               — запустить сценарий
macro stop <file.lua>              — остановить
macro reload [file.lua]            — перечитать (без имени — все)
macro prio <file.lua> <+1|-1>      — изменить приоритет
macro msg <слова...>               — событие для term-обработчиков (полное совпадение)
macro btn <имя...>                 — событие для button-обработчиков
```

Примечания: вывод в терминале — только латиница; сообщения модуля начинаются с `[MACRO]`;
сценарий печатает функциями `print`/`log`/`puts` (с префиксом `[MACRO]`).

## 5. Язык сценариев (реальный Lua)

### 5.1 Файл = Lua-чанк, тело тикает раз в секунду

Тело файла (top-level) исполняется на каждом тике. Операторы тела — это и есть реактивная
логика. Дополнительно `tick(fn)` регистрирует функцию на каждый тик.

```lua
-- тело: исполняется каждую секунду
if time.hour >= 22 or time.hour < 8 then
    if veml7700.available and veml7700.lux < 20 then
        e7.brightness = 5
    end
end
```

### 5.2 Ресурсы через namespace-таблицы

Namespace ресурсной шины доступен как таблица. `ns.field` читает/пишет состояние,
`ns.func(args...)` вызывает функцию.

| Операция | Пример |
|----------|--------|
| Чтение | `local lux = veml7700.lux`, `if wifi.connected then` |
| Запись | `e7.brightness = 5`, `wifi.target = "ap"` |
| Вызов | `e7.speed(50)`, `wifi.force_connect()` |

Типы при чтении: `BOOL` → `true/false`; `I32`/`F32`/`TIME` → число; `STR` → строка;
`ENUM` → **каноничное строковое имя** (например `wifi.target` → `"sta"`).

**Dual-ресурсы** (состояние + write-функция: `e7.speed`, `e7.brightness`, `e7.effect`,
`wifi.mode`): `ns.field` возвращает **вызываемый** объект. Запись `e7.brightness = 5` и вызов
`e7.speed(50)` применяются через write-функцию. Прочитать текущее состояние dual-ресурса
напрямую (`e7.brightness`) нельзя — используйте `get("e7.brightness")` или `info(...)`.

### 5.3 ENUM — только строки

Запись ENUM-ресурса принимает **только буквенное имя** из каталога ресурсов; число — ошибка
(`enum ... requires name, got number`), неизвестное имя — `unknown enum value 'foo'`.
Регистр не важен.

```lua
wifi.target = "ap"
e7.effect = "rainbow"
```

### 5.4 Персистентное состояние `state`

Таблица `state` (одна на файл) живёт между тиками и очищается при остановке/перезагрузке
сценария — используйте её для фронтов и памяти:

```lua
if veml7700.lux < 20 and state.brightness ~= 5 then
    state.brightness = 5
    e7.brightness = 5
end
```

### 5.5 Запись дедуплицируется на шине

Если `set`/`ns.field = v` записывает значение, равное текущему, ничего не происходит: ни
событие `state.*`, ни вызов write-функции. Поэтому для состояния `state` часто не нужен —
пишите условие прямо в теле. **Вызовы** `ns.func(...)`/`call(...)` не дедуплицируются: для них
фронт делайте через `state`.

### 5.6 Планировщик (глобалы)

| Функция | Назначение |
|---------|-----------|
| `every(pattern_or_seconds, fn)` | cron (6 полей, секунды первыми; 5 полей дополняются нулём) или каждые N секунд |
| `after(seconds, fn)` | один раз через N секунд |
| `once(fn)` | на следующем тике |
| `tick(fn)` | каждый тик (в дополнение к телу) |

Регистрация идемпотентна: повторная регистрация того же места/шаблона заменяет обработчик,
расписание сохраняется. `after`/`once`/`tick` регистрируйте внутри другого обработчика; вызов
их прямо в теле файла перевооружается каждый тик.

### 5.7 События (глобалы)

| Функция | Назначение |
|---------|-----------|
| `on(event_name, fn)` | событие ресурсной шины; `fn(ev)`, `ev.value` — значение |
| `term(spec, fn)` | терминал `macro msg <spec>` (полное совпадение) |
| `button(name, fn)` | `macro btn <name>` / кнопка веб-страницы |

Handler получает таблицу `ev`: `type` (`"cron"`/`"every"`/`"after"`/`"once"`/`"tick"`/`"on"`/
`"term"`/`"button"`), `spec`, `value` (для `on`).

### 5.8 Прочие глобальные функции

- `print(...)` / `log(...)` / `puts(...)` — вывод в терминал с префиксом `[MACRO]`;
- `now()` — секунды, `clock()` — `"HH:MM:SS"`;
- `has(name)` / `info(name)` — проверка/метаданные ресурса (`kind`, `rw`, `func`, `async`,
  `event`, `enum`);
- `mode(ns [, value])` — режим модуля: чтение/запись (`"off"`/`"auto"`/`"macro"` или индекс);
- `meta{ desc = "..." }` — описание файла для таблицы;
- `get(name)` / `set(name, v)` / `call(name, ...)` — строковые аналоги `ns.field`.

### 5.9 Ошибки сценария

Ошибки компиляции и исполнения попадают в `err` файла (колонка таблицы):

- `enum ... requires name, got number` — число для ENUM;
- `unknown enum value 'foo'` — неизвестное имя ENUM;
- `cron error: ...` — невалидное cron-выражение;
- `set <res>: <код>` — ошибка записи (`DENIED`/`READONLY`/…);
- `attempt to index a nil value` — обращение к незарегистрированному namespace;
- `scenario step limit exceeded` — сработал лимит инструкций (защита от бесконечного цикла).

### 5.10 Цвета

Цвет в сценариях и конфигах — **только строка** `"#RRGGBB"` (CSS-хекс, 6 цифр). Числа,
`#RGB`, `0xRRGGBB`, имена цветов и другие формы не принимаются. Регистр ввода любой, вывод —
верхний.

```lua
e7.color("#FF0000")
e7.color = "#00FF00"
set("e7.color", "#0000FF")

local c = get("e7.color")   -- "#FF0000"
```

Ошибка чтения строки (JSON/веб) даёт `#FFFFFF`. Невалидная строка при явной записи из Lua/шины
возвращает `BUS_ERR_BAD_VALUE` и не меняет текущий цвет. В таблицах-конфигах храните цвета
строками:

```lua
local slots = {
    { color = "#FF0000", color2 = "#00FFFF" },
}
```

## 6. Справка по CRON

Выражение — **6 полей** (интерпретатор всегда ожидает секунды первым):

```
секунды   минуты   часы   день-месяца   месяц   день-недели
```

- секунды 0–59, минуты 0–59, часы 0–23;
- день месяца 1–31, месяц 1–12 (или `JAN`–`DEC`), день недели 0–7 (0 и 7 = воскресенье,
  или `SUN`–`SAT`);
- возможны 5 полей (без секунд — дополняются нулём) и 7 полей (год опционально).

Синтаксис поля: `*` — любое; `*/N` — каждые N; `a-b` — диапазон; `a-b/N` — шаг в
диапазоне; `a,b,c` — список; `?` — как `*`.

### Примеры

```text
"*/10 * * * * *"          -- каждые 10 секунд
"0 * * * * *"             -- каждая минута (в 0-ю секунду)
"15 42 * * * *"           -- каждый час в 00:42:15
"0 0 */2 * * *"           -- каждые 2 часа
"0 30 */4 * * *"          -- каждые 4 часа в :30
"0 0 9 * * 1-5"           -- будни в 09:00
"0 0 9-17 * * *"          -- каждый час с 09:00 до 17:00
```

Cron срабатывает **только после синхронизации NTP**; расписание считается в локальном
времени. Планировщик хранит у cron-обработчика «следующий момент» (`cron_next`), при
совпадении `now() >= next` выполняет тело и считает следующий — пропущенное не «догоняется».
При скачке времени больше `MACRO_CRON_JUMP_MAX_S` (120 с) `next` пересчитывается **без
выполнения**. `every(N, fn)` использует `millis()` и не требует NTP.

## 8. Как это устроено внутри

### Поток данных

```
web (/macros.html) ──GET──▶ web_Init-эндпоинты  → FS + /config_macros.json + флаг
                                      │
                              SetTimerTask(tick, 1000)   (main loop)
                                      │
              изменение списка → пересборка набора запущенных сценариев
                                      │
        тик: drainEvents → тело чанка (→ перерегистрация обработчиков)
             → tick-обработчики → cron/interval/after/once
```

- Интерпретатор Lua и планировщик вызываются **только в main-loop контексте** (тик EERTOS
  и терминал); веб-обработчики не трогают интерпретатор.
- **Один** `EspLuaEngine` (`_lua`) на весь модуль. При запуске файл компилируется один раз
  (`macroCompileChunk`), создаётся per-file окружение `_ENV` и таблица `state`; результат —
  ref на скомпилированный чанк. Тело вызывается на каждом тике; регистрация обработчиков
  идемпотентна (повторная регистрация заменяет обработчик).
- Lua-вызовы защищены счётчиком VM-инструкций (`MACRO_LUA_MAX_OPS`, count-hook) и порогом
  heap (`MACRO_LUA_MIN_HEAP`).

### Ресурсные прокси

- `_ENV` каждого файла имеет метатаблицу: `__index` сначала проверяет
  `core_state.hasNamespace(key)` и возвращает namespace-прокси (кэшируется в registry), иначе
  — обычный глобал (хелперы).
- namespace-прокси (`__index`/`__newindex`) резолвит `full = ns.field` в `core_state`:
  - ресурс с функцией → кэшируемый вызываемый closure (`f(args)` → `core_state.call`);
  - ресурс-состояние → нативное значение (`BOOL`/число/строка; ENUM → имя);
  - запись → `core_state.applyValue` (ENUM только строка);
- Кэши (namespace-прокси, closure, метатаблица) живут в Lua registry — не пересоздаются
  на каждом тике.

### Структуры данных (module_macros_engine.h)

- `MacroFile` — файл-сценарий: метаданные (`name`, `prio` 0..7, `run`, `created`, кэш `size`)
  + runtime (`active`, `err`, `desc`, `needParse`, `parseFails`, `chunkRef`/`envRef`/`stateRef`,
  массив `handlers`).
- `MacroHandler` — обработчик: `type` (`MACRO_H_CRON|INTERVAL|AFTER|ONCE|TICK|TERM|BUTTON|ON`),
  `key` (pattern/секунды/callsite/spec/имя события), `fnRef` (Lua registry), `expr`/`next`
  (cron), `dueMs` (interval/after/once).
- `MacroEvent` — элемент очереди внешних событий (`type`, `spec`, `value`).
- `strMacrosConfig` — `enabled`.
- Ограничения (ESP32): до 40 файлов, до `MACRO_MAX_HANDLERS = 16` обработчиков в файле,
  бюджет heap — 100 КБ (проверка `/macros/heap`).

  "files": [

  ]

Список для веба = сканирование `/macros/*.lua` + наложение меты.

### Дедупликация записи (в `core_state`)

- `writeRes()` (чистое состояние) сравнивает новое значение с текущим: равное — `BUS_OK`
  без обновления/события.
- `applyValue()` (единая запись ресурса: dual → write-функция, чистое состояние → `writeRes`)
  не вызывает write-функцию, если значение не изменилось. Используется сценариями и веб-`set`.
- `call()`/`call_async()` не дедуплицируются.

## 9. Ограничения (важно)

- Модуль собирается и работает **только на ESP32**.
- **Обратная совместимость не поддерживается.** Старый декларативный формат
  (`return { rules = {...} }`, ключевые слова `when`/`cond`/`op`/`val`/`res`/`set`/`call`/
  `calls`/`run`/`args`/`value`/`cron`/`term`/`button`/`on`/`meta_cron`/`handlers`) удалён.
  Старые сценарии нужно переписать на реальный Lua.
- **Dual-ресурсы читаются через `get()`**, а не через `.field` (см. §5.2).
- **ENUM-значения — только буквенные имена** (§5.3).
- `/macros/validate` компилирует сценарий и прогоняет тело с подавлением bus-действий
  (`set`/`call`/`mode`/планирование — no-op).
- Интерпретатор Lua использует heap: **один** `_lua` на модуль, чанки компилируются только
  у **запущенных** файлов. Следите за `/macros/heap`.
- Тело и обработчики должны быть короткими (main-loop, тик раз в секунду). Бесконечные циклы
  прерываются по лимиту инструкций.
- Перечитывание файлов — только вручную (старт/стоп/«Перечитать»/терминал); авто-детекта по
  mtime нет.
- Cron требует NTP; `every(sec)` и события работают без NTP.
- Старые файлы `*.tcl` (версия на pTcl) не поддерживаются.
- Перепрошивка FS-образа перезаписывает пользовательские правки.
- В терминал выводится только латиница (в коде — русские комментарии, в веб — русский
  интерфейс).

## Функциональные требования

- FR-MACROS-1: Единый `lua_State` на модуль (не на файл).
- FR-MACROS-2: Файл-сценарий — произвольный Lua-чанк; тело исполняется раз в секунду.
- FR-MACROS-3: Ресурсы доступны как namespace-таблицы: `ns.field` (чтение/запись),
  `ns.func(args)` (вызов); ENUM — только строковые имена; dual-ресурсы — function-first.
- FR-MACROS-4: `state` — персистентная таблица на файл; запись значений дедуплицируется на шине.
- FR-MACROS-5: Планировщик `every`/`after`/`once`/`tick`; события `on`/`term`/`button`.
- FR-MACROS-6: Cron — 6 полей (секунды первыми), 5/7 нормализуются; требует NTP;
  `every(N, fn)` использует `millis()`.
- FR-MACROS-7: Lua API: `every`, `after`, `once`, `tick`, `on`, `term`, `button`,
  `print`/`log`/`puts`, `now`, `clock`, `has`, `info`, `mode`, `meta`, `get`, `set`, `call`,
  `state`, namespace-прокси.
- FR-MACROS-8: Handler получает таблицу события (`type`, `spec`, `value`).
- FR-MACROS-9: Конфиг `/config_macros.json`: `enabled` (bool), `files[]`
  (`name`, `prio` 0..7, `run`, `created`).
- FR-MACROS-10: Лимиты: `MACRO_MAX_FILES=40`, `MACRO_MAX_HANDLERS=16`, `MACRO_EV_QUEUE=8`,
  `MACRO_MAX_EVENT_SUBS=8`, `MACRO_HEAP_BUDGET=100 КБ`, `MACRO_HEAP_CRIT_PCT=95%`,
  `MACRO_LUA_MAX_OPS=100000`, `MACRO_PARSE_PER_TICK=2`, `MACRO_PARSE_MAX_RETRY=3`,
  `MACRO_LUA_MIN_HEAP=24 КБ`.
- FR-MACROS-11: Ресурсы bus: `macros.enabled` (BOOL), `macros.files` (I32); функция
  `macros.reload`; namespace привилегированный.
- FR-MACROS-12: Редактирование/сохранение сценария — только для остановленного файла.
- FR-MACROS-13: `/macros/validate` компилирует чанк и прогоняет тело с подавлением побочных
  действий.
- FR-MACROS-14: Конфиг сохраняется только по действию пользователя.

## Ресурсы шины (namespace `macros`)

- состояния: `macros.enabled` (BOOL), `macros.files` (I32);
- функции: `macros.reload`;
- namespace привилегированный (`priv=1`).

## Критерии приёмки

- AC-11: Сценарий запускается; тело тикает; `every`/`after`/`once`/`tick` срабатывают; `on`/
  `term`/`button` принимают события; `ns.field`/`ns.func` работают; ENUM-запись — только
  строки; `state` персистентен; stop останавливает файл; при переполнении heap — предупреждение
  без падения.

## Ограничения и известные проблемы

- OPEN-4: `module_macros`: при сдвиге массива `_files` активные refs (chunk/env/state/handlers)
  принадлежат перемещаемой записи; удаление делает `unregisterFile` до сдвига, поэтому refs
  освобождаются корректно. Проверять при будущих доработках массового переименования.
