Macros — help

1. Сценарий — это настоящий Lua

Файл *.lua — обычный Lua-чанк. Его тело исполняется раз в секунду (тик главного цикла): операторы тела просто выполняются на каждом тике. Это основной способ писать реактивную логику. В модуле один Lua-интерпретатор на всё устройство; чанк компилируется один раз при запуске и вызывается на каждом тике. 

if time.hour >= 22 and veml7700.available and veml7700.lux < 20 then
    e7.brightness = 5
end

2. Ресурсы: namespace-таблицы

Namespace ресурсной шины (time, wifi, e7, veml7700, …) доступны как таблицы. ns.field читает/пишет ресурс, ns.func(args...) вызывает функцию.

ДействиеПример
Чтение состоянияlocal lux = veml7700.lux, if wifi.connected then
Запись состоянияe7.brightness = 5, wifi.target = "ap"
Вызов функцииe7.speed(50), wifi.force_connect()

Типы значений при чтении:

  • BOOL → true/false;
  • I32/F32/TIME → число;
  • STR → строка;
  • ENUM → строковое каноничное имя (например wifi.target → "sta").
Откуда берётся список ресурсов. Дерево Resources строится из файла /macros/resources.json. Файл собирается автоматически при сборке файловой системы (python/gen_resources_catalog.py) из вызовов regState/regEnum/regFunc/regEvent компонентов, включённых в сборку. Поэтому:
  • вручную файл править не нужно — при следующей прошивке ФС он перезаписывается;
  • чтобы ресурс появился в дереве, он должен быть зарегистрирован в коде литеральной строкой;
  • имена, собранные динамически, и асинхронные функции (regFuncAsync) в список не попадают;
  • актуальность списка обеспечивается регистрациями в коде, а не правкой файла.
Dual-ресурсы (состояние + write-функция, например e7.speed, e7.brightness, e7.effect, wifi.mode): ns.field возвращает вызываемый объект — используйте e7.speed(50) для вызова и e7.brightness = 5 для записи. Прочитать текущее состояние dual-ресурса напрямую (e7.brightness) нельзя — используйте get("e7.brightness").

3. ENUM — только строки

Запись ENUM-ресурса принимает только буквенное имя из каталога Resources: wifi.target = "ap", e7.effect = "mono". Число для ENUM — ошибка enum ... requires name, got number, она попадает в колонку err таблицы. Неизвестное имя — unknown enum value 'foo'. Регистр не важен.

Цвета — только строки "#RRGGBB" (CSS-хекс, 6 цифр). e7.color("#FF0000"), e7.color = "#00FF00", get("e7.color") → строка. Числа, #RGB и 0xRRGGBB не принимаются. Ошибка чтения строки даёт "#FFFFFF", невалидная запись — BAD_VALUE.

4. Состояние state

Таблица state (одна на файл) живёт между тиками — для фронтов и памяти. Очищается при остановке/перезагрузке сценария. 

if veml7700.lux < 20 and state.brightness ~= 5 then
    state.brightness = 5
    e7.brightness = 5
end
Запись значения дедуплицируется на шине: если значение не изменилось, write-функция не вызывается и событие не эмитится. Поэтому часто можно писать условие прямо в теле без state. Вызовы ns.func(...) не дедуплицируются — для них фронт делайте через state.

5. Планировщик

ФункцияНазначение
every("*/10 * * * * *", fn)cron-расписание (6 полей, секунды первыми; 5 полей дополняются нулём)
every(10, fn)каждые 10 секунд
after(5, fn)один раз через 5 секунд
once(fn)на следующем тике
tick(fn)вызывать каждый тик (в дополнение к телу)

Регистрация идемпотентна: повторная регистрация того же шаблона заменяет обработчик. after/once/tick регистрируйте внутри другого обработчика; вызов их прямо в теле файла перевооружается каждый тик. 

every("0 * * * * *", function()
    print("minute:", clock())
end)

6. События

ФункцияНазначение
on("wifi.just_connected", fn)событие ресурсной шины; fn(ev), ev.value — значение
term("temp 25", fn)терминал macro msg temp 25 (полное совпадение)
button("start", fn)macro btn start / кнопка на странице

Обработчик получает таблицу ev: type, spec, value.

on("wifi.just_connected", function(ev)
    print("connected:", ev.spec)
end)
term("temp 25", function() e7.effect = "mono" end)

8. Синтаксис cron

6 полей (секунды минуты часы день месяца месяц день недели), необязательное 7-е — год. Допустимы *, */N, a-b, a-b/N, a,b,c, ?. Генератор — на странице CRON helper. Cron требует синхронизации NTP; every(sec) и события работают без NTP.

9. Ошибки

  • enum ... requires name, got number — число для ENUM-ресурса.
  • unknown enum value 'foo' — неизвестное имя ENUM.
  • cron error: ... — невалидное cron-выражение.
  • set <res>: <код> — ошибка записи (DENIED/READONLY/…).
  • File is empty or unreadable — файл пуст/недоступен.
  • No memory for interpreter / No memory for handlers — не хватило heap; нажмите Reload.
  • scenario step limit exceeded — бесконечный цикл прерван.
  • ERR: stop scenario first — попытка сохранить запущенный сценарий.

10. Лимиты

  • Файлов в списке — до 40.
  • Обработчиков в файле — до 16.
  • Инструкций Lua на один вызов — MACRO_LUA_MAX_OPS = 100000.
  • Бюджет heap модуля — 100 КБ; кнопка «Валидация макросов» показывает состояние.
