Macros — help

1. Один «барабан» и много «иголочек»

В модуле один Lua-интерпретатор на всё устройство. При старте файл прочитывается один раз: из него извлекаются правила (cron/cond/term/button/on/body), регистрируются в общем списке, после чего файл закрывается. При срабатывании правило либо выполняет декларативный вызов ресурса, либо перечитывает файл и вызывает нужный named-handler. Поэтому десятки макросов не съедают heap на отдельные интерпретаторы.

2. Формат файла (только новый)

return {
    desc = "краткое описание для таблицы",
    handlers = {                       -- необязательно; для run="..."
        apply = function(ev) set("e7.effect", ev.args[1]) end,
    },
    rules = {
        { cron = "0 20 * * * *", calls = {
            { name = "e7.effect", args = { 4 } },
            { name = "e7.speed",  args = { 40 } },
        } },
        { cron = "30 22 * * * *", call = "e7.color", args = { 65535 } },
        { cond = { res = "wifi.connected", op = "==", val = true }, run = "apply", args = { 1 } },
        { term = "temp 25",   run = "apply", args = { 25 } },
        { button = "start",   run = "apply" },
        { on = "wifi.just_connected", run = "apply" },
        { run = "apply" },              -- тело без when: по открытию мета-окна
    },
}

3. Типы правил

whenСрабатывает
cronпо своему cron-выражению, когда мета-окно открыто
condпо фронту false -> true декларативного условия
termна команду терминала macro msg <текст> (точное совпадение)
buttonна macro btn <имя> / кнопку веб-страницы
onна событие ресурсной шины (подписка оформляется движком)
нет whenтело: по фронту открытия мета-окна; без меты — один раз при старте

4. Мета-cron — гейт окна

Поле cron в таблице файлов (мета-конфиг) — это гейт, а не исполнитель. Он проверяется каждую секунду: cron_next(expr, now-1) <= now. Пока окно закрыто, правила файла не выполняются. Мета сама тело не запускает.

Если в файле единственное cron-выражение, его выносят в мета-cron (поле cron в конфиге), а правило оставляют телом ({ run = "..." }). Для «диапазона» в мете секунды и минуты должны быть *.

5. Условия cond (декларативные)

Условие — таблица {res, op, val}, их можно объединить в массив (логическое AND). Поддерживаются операторы:

  • ==, != — равенство/неравенство;
  • <, <=, >, >= — числовое сравнение;
  • changed — сработать при любом изменении значения.
{ cond = { res = "wifi.rssi", op = "<", val = -70 }, call = "e7.brightness", args = { 10 } }
{ cond = { {res="wifi.connected", op="==", val=true}, {res="time.valid", op="==", val=true} }, run = "onOk" }

6. Действия правила

  • call = "ns.func" + args = { ... } — один bus-вызов (без Lua);
  • calls = { {name=..., args={...}}, ... } — несколько bus-вызовов подряд;
  • run = "имя" + args = { ... } — named-handler из handlers. Файл перечитывается и компилируется в момент срабатывания.

У правила должно быть ровно одно действие. Если функция шины асинхронная, движок вызывает её сам (результат пишется в лог); из Lua асинхронные вызовы недоступны.

7. Lua внутри named-handler

Доступны: get, set, call, has, info, mode, puts/print, clock, now. Нет on/off/call_async — события оформляются правилом on, асинхронность — на стороне движка.

Handler получает один аргумент — таблицу события:

  • ev.type — "cron"|"cond"|"term"|"button"|"on"|"body";
  • ev.spec — cron/term/button/имя события;
  • ev.args — массив аргументов из правила;
  • ev.value — значение ресурса (для cond, если есть).

8. Состояние между срабатываниями

Каждый вызов handler получает свежее окружение: глобальные переменные между вызовами не сохраняются. Если нужно помнить значение — храните его в ресурсе core_state (set/get).

9. Ошибки

  • legacy format: use rules with call/run — файл в старом формате.
  • cron error: ... — невалидный cron в правиле или в мете.
  • File is empty or unreadable — файл пуст/недоступен.
  • No memory for interpreter / No memory for rules — не хватило heap; авто-повтор ограничен, затем нажмите Reload.
  • call: not found <name> / call ... rc=N — ресурс не найден/ошибка вызова.
  • handler not found: <name> — в handlers нет такого имени.

10. Лимиты

  • Файлов в списке — до 30.
  • Правил в файле — до 8; bus-вызовов в правиле — до 4; аргументов в вызове — до 4.
  • Инструкций Lua на один вызов handler — MACRO_LUA_MAX_OPS = 100000.
  • Бюджет heap модуля — 100 КБ; при превышении ~95% кнопка «Валидация макросов» показывает критическое состояние.

11. Синтаксис cron

6 полей (секунды минуты часы день месяца месяц день недели), необязательное 7-е — год. Допустимы *, */N, a-b, a-b/N, a,b,c, ?. Генератор — на странице CRON helper.
